# 典故源与典故的数据模型

## 结论

应把“故事”与“由故事产生的表达”分开。故事是可复用的知识实体（`allusion_origins`），典故是实际用于写作和检索的表达（`allusions`）；二者通过 `allusion_origin_links` 关联。不要把“七步诗、七步才、陈思七步”当作一个典故的别名：它们能独立释义、举例和评估频率，是同源的不同表达。只有异体字、繁简体或纯书写差异才进入 `allusion_aliases`。

关系使用连接表而非在典故表上放单一外键，原因是少数表达可能融合多个来源，且编辑需要注明“主要来源、变体、相关材料”。日常数据仍应恪守一个主要来源：同一典故至多一条 `is_primary = true` 的关系（D1/SQLite 无法用普通约束表达此条件，写入服务需校验）。

## 字段职责

### `allusion_origins`：共享故事

- `classical_text`：经过校勘、用于展示的典源原文；
- `vernacular_story`：编辑撰写的白话叙事，不与翻译混用；
- `story_dynasty` / `story_period`：故事发生时代。它不是成书朝代；
- `note`：版本流传、史实争议和校勘说明；
- `status`：故事也独立审核和发布，避免已发布典故意外露出草稿来源。

### `origin_sources`：出处与版本证据

出处不是故事上的一组字符串，而是一对多的文献记录。`work_id` 指向作品，并从 `works` 取得作者与**成书朝代**；`chapter` 记录篇章，`source_type` 区分最早出处、后出材料和流传版本。`original_text` 可记录该版本独有的文本，`translation` 是该段原文的直译，`reference_note` 保存卷次、版本、页码等可核查信息。

这能正确表达示例中的两层材料：《世说新语·文学》是主要典源，《漫叟诗话》是四句本的流传证据，而不是另一个故事。

### `allusions`：可使用的表达

- 每条记录只代表一个可独立检索、释义和引用的表达；
- `meaning`、`usage_notes` 和例句均属于表达，不属于共享故事；
- `frequency_level` 是 1–5 的编辑等级（罕见、较少、一般、常见、高频）；
- `frequency_note` 必须说明判断依据，例如语料库、统计区间，或“编辑初评”。

频率不是故事的属性，也不应直接用例句条数推导。例句是策展数据，条数受编辑完整度影响。未来若接入语料库，应另建带 `corpus`、`period_start`、`period_end`、`sample_size`、`count`、`normalized_rate` 的观测表，再由规则生成当前等级。这样不会把一个随时间和语域变化的数字伪装成永恒事实。

## “七步成诗”示例

建立一个“曹植七步成诗”的典故源，白话故事只维护一次；连接“七步诗”（常见）、“七步才”（一般）、“陈思七步”（罕见）三条典故。每条典故保留自己的释义、用法、用例和频率依据。详情页展示共享故事、出处版本，以及按频率排列的同源典故。

“诗成七步”也应作为独立表达；若后续证据表明它仅是语序变化且没有独立用法，才降级为别名。这个判断应基于语料，而不是仅凭字面相似。

## 迁移策略

1. 新数据只在典故源维护故事；`allusions.story` 暂留作旧数据兼容字段。
2. 按故事聚类旧典故，创建典故源和主要关系；人工复核后发布典故源。
3. 将旧 `allusion_sources` 搬到 `origin_sources`，但属于单个表达的用例继续保留在 `examples`。
4. 页面优先展示已发布典故源；没有关系时回退旧 `story` / `allusion_sources`。
5. 完成迁移并检查无孤儿数据后，再以单独 migration 删除旧字段和旧出处表。

这种分阶段方式可避免一次性破坏现有页面，也保留回滚和审计空间。
